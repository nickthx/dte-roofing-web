# Plan 01-01: Root-Cause Diagnosis — Duplicate Metadata & /blog SSR

**Phase:** 1 — Diagnosis & Competitor Research
**Milestone:** v1.1
**Requirements:** META-03, BLOG-03
**Estimated tasks:** 5
**Depends on:** Nothing (first plan)

## Goal

Identify the exact code path causing 21 pages to share the same 166-char default title + 35 pages to share the same homepage meta description, and the code path causing `/blog` to ship empty `<title>` and empty `<h1>` in prerendered HTML. Produce a diagnosis note that tells Phase 2/3/4 executors *exactly* which files to edit.

## Context

- v1.0 phase M8B landed prerender with react-helmet-async SSR (commit `f144e2e`).
- v1.1 audit (2026-04-08) confirmed prerender IS working — `/locations/columbus/index.html` has `<title data-rh="true">Roofers Columbus, OH | DTE Roofing — Roof Repair & Replacement</title>`.
- But 21 other pages share: `"BEST Roofer in Columbus – if you're looking for Honest Roofing Services near me or Expert Roof Repair & Replacement near me – DTE Roofing is the place to be."` (166 chars)
- All 35 pages share the homepage meta description verbatim.
- `/blog` ships empty `<title>` (0 chars) and empty `<h1>`.
- Every page in `src/pages/` imports `SEO` (verified via grep in prior session).
- `SEO.tsx` is a thin wrapper over `<Helmet>` — it only renders what's passed to it.

**Hypothesis:** Either (a) a shared template (e.g., `ServicePageTemplate.tsx`) passes a hardcoded fallback title/description, or (b) the 21 pages omit the `title`/`description` props entirely and something (index.html static tags?) bleeds through. The /blog issue is almost certainly Supabase async data-loading causing SSR to render `null` or a loading state.

## Tasks

### Task 1: Inventory <SEO> usage across all 35 sitemap pages
**What:** Grep each page file for `<SEO ` and extract the title/description props (or absence of).
**Output:** Table in `RESEARCH.md` with columns: `page path | file | has <SEO>? | title prop | description prop | source of title`

**Command:**
```bash
for f in $(find src/pages -name "*.tsx"); do
  echo "=== $f ==="
  grep -A5 "<SEO" "$f" | head -15
done
```

Classify each page into one of:
- **A** — passes unique `title` and `description` props inline ✅
- **B** — passes only `title`, no `description`
- **C** — passes neither, relies on a default somewhere
- **D** — uses a shared template that passes hardcoded values
- **E** — `/blog` edge case (async data-loading)

**Acceptance:** Every page in `src/pages/` that corresponds to a sitemap URL has a classification letter assigned.

### Task 2: Find the default/fallback title source
**What:** Trace where the 166-char `"BEST Roofer in Columbus – if you're..."` string lives.

**Approach:**
```bash
grep -rn "BEST Roofer in Columbus" src/
grep -rn "if you.re looking for Honest" src/
```

It's either:
- Hardcoded in `SEO.tsx` as a default prop value
- In `ServicePageTemplate.tsx` as a fallback
- In `index.html` as the `<title>` that prerender fails to override when Helmet has no title
- In a constant file (e.g., `src/seo/*.ts`)

**Acceptance:** The exact file + line of the 166-char fallback is documented.

### Task 3: Find the default meta description source
**What:** Trace where `"DTE Roofing - Professional roofing services in Columbus, Hilliard, and Dublin, OH. Expert roof repair, replacement, installation, and emergency services. Licensed, bonded & insured. Free estimates."` (197 chars) lives.

**Approach:**
```bash
grep -rn "Licensed, bonded & insured. Free estimates" src/ index.html
```

Most likely in `index.html` as a static `<meta name="description">` — and the 13 location pages have `<Helmet>` titles but *don't pass descriptions*, so Helmet doesn't emit a description tag and the index.html static one bleeds through unchanged.

**Acceptance:** The exact source file + line of the 197-char default description is documented.

### Task 4: Diagnose /blog empty head
**What:** Read `src/pages/Blog.tsx`. Determine if the `<SEO>` component is:
- Missing entirely
- Rendered inside a conditional that evaluates false during SSR (e.g., `loading ? null : <><SEO /> ... </>`)
- Using dynamic data (post title) that's `undefined` at SSR time

**Acceptance:** RESEARCH.md contains the exact line number and reason why SSR emits empty `<title>`. Include a proposed fix approach (e.g., "move `<SEO title='Roofing Tips & News | DTE Roofing Blog' description='...' />` above the loading check so it renders unconditionally").

### Task 5: Write RESEARCH.md with fix strategy
**Output:** `.planning/phases/01-diagnosis-competitor-research/RESEARCH.md` containing:
1. Summary table from Task 1 (35 rows, classification letter per page)
2. Default title fallback location (Task 2)
3. Default description fallback location (Task 3)
4. `/blog` root cause + proposed fix (Task 4)
5. **Fix strategy:** One of:
   - **S1** — Single-point fix in `ServicePageTemplate.tsx` or `SEO.tsx` propagates to N pages
   - **S2** — 22 per-page edits needed (plus 13 location descriptions)
   - **S3** — Hybrid: fix default + edit some pages
6. **Impact map:** Which phases (v1.1 Phase 2/3/4) need which edits based on the fix strategy chosen

**Acceptance:**
- RESEARCH.md exists and is non-empty
- Fix strategy is explicitly named S1/S2/S3 with reasoning
- Subsequent phases have a clear action list
