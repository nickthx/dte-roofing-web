## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Network-error detail lost the reason when undici gives no cause code**
- **Found during:** Task 2, step 6 (the `http://127.0.0.1:9` case)
- **Issue:** The plan assumed port 9 gives a connection refusal with `err.cause.code`. Port 9 is on the Fetch spec's blocked "bad port" list, so undici rejects it before connecting with `cause = Error('bad port')` and no `code`. The row read only `fetch: fetch failed`.
- **Fix:** The detail is now `fetch: <message> (<cause.code ?? cause.message>)`. Port 9 gives `fetch failed (bad port)`. A genuinely refused port (59999) gives `fetch failed (ECONNREFUSED)`, as the plan intended.
- **Files modified:** `scripts/verify-schema.mjs` (in commit 0283c37)

### Other notes (no output impact)

- **Extra live tests.** Beyond the plan, the script was also run against a bogus prefix (non-200 → 41 × `fetch: 404`), the apex host (proves redirect following) and a refused port. Total production load from verify-schema live runs was about 5 × 41 sequential GETs plus 41 apex redirects. The threat model estimated 2 × 41. It is still negligible.
- **TDD gate.** The task is `tdd="true"`, but the constraints allow exactly one commit containing only `scripts/verify-schema.mjs`. So there is no separate `test(...)` commit. RED was shown by running the behavior cases against the unmodified script: `--base` was silently ignored, exit 0. GREEN was shown by the table above.
- **Poll script.** It also requires HTTP 200 for "flipped", which is stricter than the spec and had no effect. It allows 19 attempts with a 570 s wall cap.
- **Line endings.** `core.autocrlf=true` (system gitconfig). `git checkout main` removed the files that exist only on the branch, and the fast-forward re-created them as CRLF in the working tree.
