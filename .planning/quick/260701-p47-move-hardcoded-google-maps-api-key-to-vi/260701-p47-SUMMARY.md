# Quick Task 260701-p47: Move Hardcoded Google Maps API Key to Vite Env Var Summary

Moved the hardcoded Google Maps browser API key out of tracked source into the Vite env var `VITE_GOOGLE_MAPS_API_KEY`; `ServiceAreaMap` now reads it via `import.meta.env`, degrades gracefully (returns `null`, rejects before any `<script>` injection) when unset, and is backed by a gitignored `.env` plus a committed `.env.example`.

## What Was Built

- **Task 1 — Typed env access** (`src/vite-env.d.ts`, commit `510fbd3`): Added `ImportMetaEnv` interface declaring `readonly VITE_GOOGLE_MAPS_API_KEY: string` and `ImportMeta` with `readonly env: ImportMetaEnv`, alongside the retained `vite/client` reference. Gives strict-mode type coverage for the property access added in Task 2.
- **Task 2 — Env-driven, graceful component** (`src/components/ServiceAreaMap.tsx`, commit `101ecc2`):
  - Replaced the literal `const API_KEY = 'AIzaSy...'` with `const API_KEY = import.meta.env.VITE_GOOGLE_MAPS_API_KEY;` (no fallback literal).
  - Added a guard as the **first** statement inside the `loadGoogleMaps()` Promise executor: when `!API_KEY`, it `reject(...)`s and `return`s before any `document.querySelector` or script creation — so no `<script>` with `key=undefined` is ever appended. The existing `.catch(console.error)` in the `useEffect` chain surfaces this as the single required `console.error`.
  - Changed the return type to `JSX.Element | null` and added `if (!API_KEY) return null;` after all hooks (`useRef` x2, `useCallback`, `useEffect`) run — hook ordering preserved.
- **Task 3 — Env files + build gate** (`.env.example` committed as `a64cdf5`; `.env` created untracked): `.env` holds the real working key for local dev/build; `.env.example` documents the variable with a placeholder. `npm run build` passes (exit 0).
